# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Super Mushroom Sprint — a 3D Mario-style browser platformer. Zero external assets: every texture (Canvas-generated), model (Three.js boxes), and sound (WebAudio synthesis) is produced in code. The production build is a single self-contained `dist/index.html` via `vite-plugin-singlefile`. Originally generated by arena.ai from a one-line prompt, then refined locally (see README for the fix log).

## Commands

```bash
pnpm install        # or npm install — note both package-lock.json and pnpm-lock.yaml exist
pnpm dev            # dev server → http://localhost:5173
pnpm build          # emits single self-contained dist/index.html
pnpm preview        # preview the build
npx tsc --noEmit    # type check (tsconfig is strict + noEmit; there is no test or lint script)
bun tools/levelcheck.ts        # QA scripts — run directly with bun or npx tsx, NOT via package.json
bun tools/dump.ts <seed> <x0> <x1>   # print block/enemy/coin layout for an X range
```

Requires Node 20.19+ or 22.12+ (Vite 7 constraint). There are no unit tests; correctness is checked with `tsc --noEmit`, `vite build`, and the deterministic QA scripts in `tools/` (levelcheck/gapcheck/enemycheck sweep hundreds of seeds for NaN, unjumpable gaps, floating enemies).

## Architecture

### Two-layer split: React shell ↔ imperative engine

The React tree (`src/App.tsx`, `src/ui/`) never touches game state directly. `App.tsx` creates one `Game` instance (`src/game/engine.ts`) inside a `useEffect`, passes an `onHud` callback (state snapshots ~every frame) and an `onEnd` callback (run results). React re-renders purely off the `Hud` object and switches screens on `hud.phase`. All control flows the other way as imperative method calls: `gameRef.current?.startRun()`, `restart(sameSeed)`, `setMove()`, `jumpDown/Up()`, `spin()`, `togglePause()`, `toggleCamera()`.

Phase state machine lives in the engine: `menu → playing → (paused | dying → dead | clearing → clear)`. React screens exist for `menu`, `paused`, `dead`, `clear`; transient phases `dying`/`clearing` keep the HUD up.

**Gotcha for UI work:** `App.tsx` calls `submit()` before every restart/menu path so run scores are never lost when the user hits Enter/R shortcuts — preserve that ordering when adding new navigation paths.

### Engine (src/game/engine.ts, ~1600 lines — the core of the project)

- `Game` class owns the Three.js renderer, both canvases (WebGL scene + 2D overlay for floating text), physics, enemies, camera, and the run loop.
- **Fixed timestep:** `requestAnimationFrame` accumulates time and steps physics at exactly 1/120s (max 5 catch-up steps per frame, then the accumulator is dropped). Hit-stop sets sim time to 0 and slow-mo multiplies it by 0.32 — both scale *simulation* time only; rendering, camera, and FX always update with real `dt`. Touch game-feel tuning through `PHYS`/`SCORE`/`COMBO_MULT` in `src/game/constants.ts`, not inline magic numbers.
- **Collision:** AABB with a spatial hash (`SLAB = 6` world units) mapping X-slab → solids. Resolution is per-axis push-out plus a `STEP_UP` (0.62) ledge assist. Spikes are hazards, not solids.
- **Camera:** smooth follow-yaw (`camYaw`); movement input is camera-relative (W always pushes away from the camera), computed in `step()` via `camYaw` sin/cos. Two modes: `follow` and `fp` (first-person hides the hero model + blob shadow, wider FOV).
- Enemies are a `walk | shell | slide | dead` state machine (koopa shells slide and chain-kill).

### Level generation (src/game/level.ts + rng.ts)

`generateLevel(seed)` is a **pure, deterministic function** (xorshift32 PRNG in `rng.ts`). A `Builder` accumulates solid/coin/enemy/qblock defs; chunk functions (meadow, hopGaps, pipeGarden, blockLine, staircase, cloudFloat, spikeBridge, ridgeRun, springTower) are chained along a cursor with a difficulty ramp, checkpoint plazas at fixed indices, and a goal section. Two coordinate conventions matter: `plat(x0, x1, top, ...)` takes the top surface Y; `block(cx, bottom, cz, ...)` takes the bottom Y.

**Do not introduce nondeterminism** (Math.random, Date.now) into `generateLevel` or the chunk functions: the `tools/` QA scripts import it directly to sweep hundreds of seeds, and the game's "retry same seed" feature depends on it. Seeded randomness must come from the `Rng` argument. Enemy *runtime* behavior may use `Math.random` freely.

### Rendering/asset pipeline

- `models.ts` builds all characters/props from `BoxGeometry`; `textures.ts` generates Canvas pixel textures and `tiledBox()` tiles UVs by world size so textures stay crisp at any scale. No shadow maps — a `CircleGeometry` blob shadow tracks the player.
- Coins, clouds, and particles render as `InstancedMesh` pools (mobile DPR is capped; antialiasing off on coarse pointers).
- `fx.ts` pools particles/rings/shockwaves and floating text (2D overlay canvas); `audio.ts` synthesizes SFX and two BGM loops, unlocked on first user gesture, mutable via `sound.setMuted()`.
- `storage.ts` persists the local top-8 leaderboard and player name in `localStorage`.
- `window.__game` handle exists **only in `import.meta.env.DEV`** — used by headless-browser probes; keep it out of production code paths.
